# Telegram-бот для офлайн-ивента

Шаблон бота для конференций, форумов, кейс-чемпионатов и других ивентов,
куда люди приходят по списку. Использовался на двух живых ивентах.

Состоит из трёх модулей, каждый можно выключить:

- **Сверка участников.** Пришедший нажимает /start, бот ищет его в списке
  прошедших отбор (Google-таблица) по нику, потом по телефону. Кого нет в
  списке — бот отправляет на стойку регистрации, а организаторы получают
  карточку с кнопками «Подтвердить / Отказать».
- **Программа ивента.** Организаторы загружают её прямо из Telegram
  текстом или картинкой.
- **Бинго.** Сетка заданий («сфотографируйся со спикером», «найди
  партнёрский стенд»). Участник отправляет пруф (фото, альбом, текст,
  ссылку), организаторы принимают или отклоняют его кнопкой в админ-чате,
  выполнивший все задания становится победителем.

Плюс: дублирование всех данных в Google-таблицу, выгрузка в Excel,
антиспам, восстановление после сбоев, три уровня сброса данных.

## Быстрый старт

Нужны: токен бота от [@BotFather](https://t.me/BotFather), свой Telegram ID
(узнать у [@userinfobot](https://t.me/userinfobot)) и группа для
организаторов, куда добавлен бот.

```bash
cp .env.example .env    # заполни BOT_TOKEN, ADMIN_IDS, ADMIN_CHAT_ID
docker compose up -d --build
```

Docker Compose поднимет PostgreSQL и бота. Схема базы создаётся сама.

Без Docker нужен Python 3.12+ и PostgreSQL:

```bash
pip install -r requirements.txt
cp .env.example .env    # плюс DATABASE_URL
python bot.py
```

Отправь боту /start, а с аккаунта админа — /admin, чтобы увидеть команды.

## Как переделать под свой ивент

| Что | Где |
|-----|-----|
| Название ивента, канал, часовой пояс | `.env`: `EVENT_NAME`, `CHANNEL_URL`, `TIMEZONE_OFFSET` |
| Какие модули включены | `.env`: `FEATURE_SCREENING`, `FEATURE_AGENDA`, `FEATURE_BINGO` |
| Все тексты и кнопки для участников | `content/texts.py` |
| Задания бинго | `content/tasks.py` |
| Список участников для сверки | Google-таблица, см. [docs/google-sheets.md](docs/google-sheets.md) |

Число заданий любое: сетка подстраивается сама (9 → 3×3, 16 → 4×4).
Порог победы — `WIN_THRESHOLD`, по умолчанию все задания. Описания и
фото-образцы заданий админы могут менять прямо в боте (`/edit_desc`,
`/upload_task`); `/reseed_tasks` подтягивает правки из `content/tasks.py`,
не затирая ручные.

Все настройки с пояснениями — в [.env.example](.env.example).

## Команды

**Участник:** `/start`, `/menu`, `/agenda`, `/bingo`, `/tasks`, `/cancel`.

**Админ** (Telegram ID в `ADMIN_IDS`) — `/admin` покажет всё, что доступно
с текущими модулями:

| Модуль | Команды |
|--------|---------|
| всегда | `/whois`, `/export`, `/exportcsv`, `/reset_all` |
| сверка | `/pending`, `/verify`, `/check`, `/delegates`, `/sync_delegates`, `/reset_registrations` |
| бинго | `/list_tasks`, `/upload_task`, `/edit_desc`, `/reseed_tasks`, `/muted`, `/unmute`, `/reset_game` |
| программа | `/set_agenda`, `/clear_agenda` |
| таблица | `/queue`, `/resync_sheets`, `/restore_from_sheets`, `/reset_sheet_cache` |

Кнопки под пруфами и карточками может нажимать любой участник
админ-чата, даже если его нет в `ADMIN_IDS`.

Подготовка к ивенту и что делать при сбоях — [docs/runbook.md](docs/runbook.md).

## Деплой

Боту нужен только исходящий доступ в интернет: он сам опрашивает
Telegram, порты открывать не надо.

**VPS / свой сервер** — `docker compose up -d --build`. Данные базы
лежат в томе `pgdata` и переживают пересборку.

**Railway / Render / Heroku и похожие.** Подключи репозиторий, добавь
PostgreSQL, задай переменные из `.env.example`. Процесс запуска описан
в `Procfile` (`worker: python bot.py`) и `Dockerfile`. Если у хостинга
есть внутренний и публичный адрес базы (как у Railway), задай
публичный в `DATABASE_FALLBACK_URL` — бот переключится на него, если
внутренняя сеть не поднимется.

Проблемы с подключением к базе: `python tools/check_db.py "<DATABASE_URL>"`
по шагам покажет, где ломается — DNS, TCP или SSL.

## Как устроено

```
bot.py              точка входа: подключает модули по флагам
config.py           настройки из переменных окружения
content/            тексты и задания — правит организатор
handlers/           хендлеры, по файлу на модуль
  start.py            /start, сверка, меню
  agenda.py           программа ивента
  bingo.py            бинго со стороны участника
  review.py           проверка пруфов, победители, антиспам
  tasks_admin.py      управление заданиями
  screening_admin.py  сверка со стороны организаторов
  admin.py            общие команды, выгрузки, сбросы
  fallback.py         ответ на непонятное
db/                 PostgreSQL по темам; схема мигрирует сама
services/           Google-таблица, очередь админ-чата, антиспам,
                    сверка, восстановление после сбоев
tg/                 клавиатуры, фильтры, состояния диалогов
tests/              тесты на живом PostgreSQL
```

Несколько решений, которые стоит знать:

- **База — источник правды, таблица — витрина.** Хендлеры не ходят в
  Google: записи копятся и уходят одним запросом раз в несколько секунд,
  так что квота не зависит от числа участников. Если упадёт база, бот
  восстановит её из таблицы; если упадёт таблица — перезальёт из базы.
- **Админ-чат через очередь.** Telegram пускает ~20 сообщений в минуту в
  группу. Очередь держит темп, переживает ошибки 429 и при наплыве
  схлопывает карточки сверки в одну сводку. Пруфы не теряются.
- **Состояния диалогов в PostgreSQL**, поэтому перезапуск не сбрасывает
  участника, который был посреди отправки пруфа.
- **Пруф привязан к своей заявке.** Двойное нажатие «Принять», два админа
  одновременно или кнопка от удалённого сбросом пруфа ничего лишнего не
  засчитают.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тестам нужен PostgreSQL: либо `TEST_DATABASE_URL` (схема в этой базе
пересоздаётся перед каждым тестом — не указывай рабочую базу), либо
пакет `pgserver` из `requirements-dev.txt`, который поднимает временный
Postgres сам. В GitHub Actions тесты и `pyflakes` запускаются на каждый пуш.
