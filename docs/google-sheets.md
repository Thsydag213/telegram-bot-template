# Google-таблица: настройка

Таблица необязательна: без неё бот работает только с базой, но тогда не
работает сверка участников (её список берётся из таблицы).

С таблицей бот читает из неё список прошедших отбор и дублирует туда
данные, чтобы организаторы видели всё в реальном времени без доступа к базе.

| Лист | Кто заполняет | Что внутри |
|------|---------------|------------|
| **Делегаты** | организаторы | список прошедших отбор: ФИО, ник, телефон. Бот дописывает справа «Статус в боте», «TG user_id», «Время входа» |
| **Регистрации** | бот | каждый, кто нажал /start: ID, ник, имя, телефон, статус сверки, первый и последний вход |
| **Прогресс** | бот | ✓/✗ по каждому заданию бинго, счётчик, время победы |

Названия листов меняются переменными `SHEET_DELEGATES`, `SHEET_REGISTRATIONS`,
`SHEET_PROGRESS`. Листы выключенных модулей бот не создаёт.

Строки подсвечиваются по статусу: 🟩 подтверждён · 🟦 подтверждён вручную ·
🟨 данные не сверены · 🟥 нет в списке.

Если Google недоступен, бот продолжает работать: сверка идёт по копии
списка в базе, а записи копятся и уходят в таблицу, когда связь вернётся.

---

## 1. Проект в Google Cloud

1. Открой [console.cloud.google.com](https://console.cloud.google.com/) под
   аккаунтом, которому принадлежит таблица.
2. Селектор проектов вверху слева → **New Project** → любое название → **Create**.
3. Убедись, что в селекторе выбран новый проект.

## 2. Включить два API

**APIs & Services → Library**, найти и включить (**Enable**):

- **Google Sheets API** — чтение и запись;
- **Google Drive API** — доступ к файлу.

## 3. Service account и ключ

1. **APIs & Services → Credentials → + Create Credentials → Service account**.
2. Любое имя → **Create and Continue**. Роль можно не выбирать → **Done**.
3. Открой созданный service account → вкладка **Keys** →
   **Add Key → Create new key → JSON**. Файл скачается.

> ⚠️ Этот файл — пароль от таблицы. Не коммить его в git. В `.gitignore`
> уже закрыты `service-account*.json`, `*credentials*.json` и `*-key.json` —
> назови файл по одному из этих шаблонов.

В файле есть поле `"client_email"` — адрес вида
`имя@проект.iam.gserviceaccount.com`. Он нужен на следующем шаге.

## 4. Дать доступ к таблице

1. Создай таблицу или открой существующую.
2. **Share / Настройки доступа** → вставь `client_email` → права **Editor**.
3. Сними галку «Notify people» → **Share**.

## 5. ID таблицы

Часть URL между `/d/` и `/edit`:

```
https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz/edit#gid=0
                                      └──── GOOGLE_SPREADSHEET_ID ────┘
```

## 6. Лист со списком участников

Создай лист **Делегаты** (или дай боту создать его) и залей список.
Шапка — в первой строке.

| ФИО | Telegram | Телефон | Email |
|-----|----------|---------|-------|
| Иван И. | @ivan_example | +7 700 000 00 01 | ivan@example.com |
| Анна А. |  | 87000000002 | anna@example.com |

- **Порядок колонок любой**, лишние не мешают. Бот находит нужные по
  словам в шапке: `ник / username / telegram / тг / аккаунт`,
  `телефон / phone / номер / контакт`, `фио / имя / name / участник`,
  `email / почта`. Если шапка совсем нестандартная, колонки ника и
  телефона определяются по содержимому.
- Ник можно писать как `@ivan_example`, `ivan_example` или `https://t.me/ivan_example`.
- Телефон — в любом формате: сверка идёт по последним 10 цифрам.
- Без ника — не страшно, такого участника бот найдёт по телефону.
- Три служебные колонки справа бот допишет сам.

## 7. Переменные окружения

| Переменная | Значение |
|------------|----------|
| `GOOGLE_SPREADSHEET_ID` | ID из шага 5 |
| `GOOGLE_CREDENTIALS_JSON` | **всё содержимое** JSON-файла одной строкой |
| `GOOGLE_CREDENTIALS_FILE` | или путь к файлу ключа вместо JSON-строки |

`GOOGLE_CREDENTIALS_JSON` удобен на хостингах, где нет файлов (Railway,
Render): открой файл ключа, скопируй всё вместе с `{` и `}` и вставь как есть.
Переносы внутри `private_key` уже записаны как `\n`.

`GOOGLE_CREDENTIALS_FILE` удобен локально и в Docker:
`GOOGLE_CREDENTIALS_FILE=./service-account.json`.

## 8. Проверка

1. Перезапусти бота. В логах:
   ```
   Google Sheets: подключено к таблице 1AbCd...
   Список участников обновлён: 42 записей
   ```
2. В таблице появятся листы бота с шапками.
3. Отправь боту `/start` — в «Регистрациях» появится строка.
4. `/delegates` — сколько записей загружено и какие колонки распознаны.

## Если не работает

| В логах | Причина | Что делать |
|---------|---------|------------|
| `синхронизация не настроена` | не задан ID таблицы или ключ | шаг 7 |
| `403 ... PERMISSION_DENIED` | таблица не расшарена на service account | шаг 4, права **Editor** |
| `403 ... API has not been used` | не включён Sheets или Drive API | шаг 2, нужны оба |
| `SpreadsheetNotFound` | неверный ID | шаг 5 |
| `JSONDecodeError` | ключ вставлен не целиком | скопируй файл заново целиком |
| `Список участников пуст` | лист пустой или называется иначе | шаг 6, `SHEET_DELEGATES` |

Если список не загрузился ни из таблицы, ни из копии в базе, поведение
задаёт `SCREENING_STRICT`: `false` (по умолчанию) — пускать всех и честно
писать участнику, что сверка недоступна; `true` — не пускать никого.

## Квоты Google

60 запросов чтения и 60 записи в минуту. Бот читает список раз в
`DELEGATES_REFRESH_MINUTES` минут, а все записи копит и отправляет одним
запросом раз в `SHEETS_FLUSH_SECONDS` секунд — около 12 запросов в минуту
при любом числе участников.
